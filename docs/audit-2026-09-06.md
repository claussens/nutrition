# Nutrition iOS audit — 2026-09-06

Run against `master` at `d363eca`, build 168 (`git rev-list --count HEAD`),
using the MiVista audit prompt (`mivista2/docs/ios-audit-prompt.md`) with
its twelve dimensions mapped onto this app. Unlike the prompt's read-only
brief, this run was asked to fix everything it found; every finding below
carries its fix, and the "after" gate status is recorded at the end.

## Headline

The build was green and all 92 tests passed before a line was changed, so
the app is in good shape on the mechanical gates. The one thing to read is
finding #1: every theme colorset lived under "Preview Content", which
`DEVELOPMENT_ASSET_PATHS` strips from an archive. A TestFlight build of
this app shipped with no colors at all, while the direct phone install
looked fine. Two more findings would have bitten a real user: the
HealthKit permission dialog described a different app's workouts, and a
rejected launch cache left the shas behind, so every later refresh said
"Up to date" while the app ran on the stale bundled seed. The rest is
data-loss edges, a wrong picker, dead code and drift. All of it is fixed
in this commit; the build now has zero warnings and 96 tests pass.

## Findings detail

### 1. Colors stripped from archives

What the user sees: a TestFlight build renders every `Color.theme.*` as
clear. Text painted `blackWhite` disappears against the background; the
gauges, blue lock state, green auto state and red out-of-range names all
vanish. The direct `devicectl` install (a Release build, not an archive)
keeps the assets, which is why nobody noticed. project.yml already
documents this exact mechanism for the app icon and then states that
"Preview Content" now holds only things that are fine to strip. It held
the whole color theme.

Fix: `git mv` the eleven live colorsets into `nutrition/Assets.xcassets`,
delete the unused `Automatic` colorset, correct the project.yml comment,
and add `PersistenceTests.testEveryThemeColorHasAColorset`, which asserts
`UIColor(named:)` resolves each name the theme uses. That test catches a
missing colorset (it would have flagged `SecondaryTextColor`), not the
archive stripping itself; the comment in project.yml now carries the rule.

### 2. HealthKit copy and scope

The permission sheet said "Your workout related data will be used to
display your saved workouts in MyWorkouts" and asked for write access to
active energy. The app reads body mass, body fat percentage and active
energy and writes nothing. Date of birth was also requested and never
read (`getAge` had been commented out).

Fix: one accurate `NSHealthShareUsageDescription`, the update-description
key removed, `toShare: nil`, date of birth dropped from the read set.
`HealthStore.swift` now states that a new read type needs new copy.

### 3. Rejected cache, sticky shas

Trace: `loadInitial` parses the Documents cache, `ConfigSync.validate`
fails it, the catch logs and loads the bundled seed. `ConfigStore.shas`
in UserDefaults still describe the rejected files, and the files still
exist, so `ConfigSync.refresh` step 3 (`newShas == cachedShas &&
cacheFilesExist()`) returns `.upToDate` on every pull until the repo
changes. The user sees "Already up to date" while eating the seed's data.

Fix: `saveShas([:])` in that catch, so the next refresh re-fetches,
re-validates and re-applies.

### 4. Bundled seed drift

`rda.yaml` in the bundle had vitamin D's upper limit at 0 for every band,
so the over-UL warning could never fire on a fresh install or after a
cache rejection; `food.yaml` was missing Creatine Monohydrate and Naked
Whey Isolate, and caden's meal carried bread amounts of 2 and 4 instead
of 56 and 112 grams. Fix: the five bundled files now equal `origin/main`
(`ae8f7e9`). ConfigSmokeTests and CostMathTests run against the bundle,
so the refreshed seed is proven to parse, validate and bridge.

### 5. History file

`DayLogMgr.init` used `try?` on both the read and the decode. A file that
exists but no longer decodes (any future `DayLog` shape change) started
the manager empty, and the next Log Today serialised a one-entry array
over the old history. Fix: decode failure moves the file to
`daylog.corrupt.json` first; the file URL is injectable so
`PersistenceTests.testCorruptHistoryIsMovedAsideNotOverwritten` proves it
with a scratch file rather than the simulator's real history.

### 6. Emptied meal reseeds

`loadOrSeed` treated a saved empty array like a missing key. Fix: only a
nil load (never saved, or corrupt and backed up) reseeds from config.
`PersistenceTests.testEmptiedMealStaysEmptyAcrossReload` pins it.

### 7. Adjustment picker names the wrong thing

Meal rows are keyed by Food name (`MealResolver` comments, every
`resetMealIngredients` branch). `AdjustmentAdd` offered every ingredient
variant name instead, so a rule for "Eggs (Vital Farms)" never matched
the "Eggs" row; the engine resolved the literal name and appended a
second row. Fix: the picker lists `foodMgr.namesSorted` minus Foods that
already have a rule, Save is disabled until one is chosen, and the label
reads "Food". The now-orphaned `getNewMealIngredientNames` is gone.

### 8. HealthKit on the hot path

`generateMeal()` runs on appear, on pull-to-refresh, and on every
stepper tap, lock toggle, variant switch and sheet save. Each call
re-requested HealthKit authorization and issued three queries, one of
which threw its sample away. Fix: `refreshFromHealthKit()` runs from
`onAppear` and `.refreshable` only, and only when the profile actually
sources a value from Health; the discarded active-energy query is
deleted. `generateMeal()` is now the pure planner call.

### 9. Deprecated navigation

`Tabs` now wraps each tab in `NavigationStack` (the deployment target is
16.0, so this needs no availability check) and MealList's three hidden
`NavigationLink(isActive:)` backgrounds are `navigationDestination(
isPresented:)` modifiers. The build is warning-free.

### 10 and 11. Dead code

Removed as listed in the table. `Ingredient` lost seven fields the config
cannot author, its `init(from:)` and `flatIngredientDict` shrank to
match, and the no-op setters on the per-100g accessors are gone.
`undoManualAdjustment` stays: the UI does not call it, but
`MealIngredientAdjustmentTests` pins it. `IngredientRow` dropped the
macro columns nothing rendered. Net: about 220 lines of Swift removed.

### 12 through 15

Small hygiene fixes, applied as described in the table. The README now
says what the app is and where to start reading; `AGENTS.md` already
carried the build recipes.

## Unverified

- The `verified:` field is decoded as a String; an unquoted YAML date in
  a future row would decode as a string under Yams, but this was not
  exercised with a real date value.
- `ProfileMgr.profile`'s getter builds a throwaway placeholder profile
  when `profiles` is empty; no path leaves it empty, but nothing forbids
  one.
- `MealIngredientMgr.automaticAdjustment(name:)` and the planner match by
  name, so two duplicate rows of one Food are auto-adjusted as the first
  row only. Duplicates are a documented feature (double-tap); whether the
  first-row rule is the intended one was not confirmed with Shane.

## Style

- Eight `.font(.system(size:))` sites (gauges, the compact toolbar)
  ignore Dynamic Type by design; left alone.
- `NameValue` still carries the unused `validator` parameter its own TODO
  describes; touching it means touching every call site, so it stays.
- `Profile.age` and the day-log key use `Calendar.current` and `Date()`
  directly; there is no debug clock in this app, so that is correct here.
